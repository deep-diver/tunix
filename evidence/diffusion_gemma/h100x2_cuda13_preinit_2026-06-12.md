# DiffusionGemma H100x2 CUDA13 Preinit Comparison

Date: 2026-06-12

## Setup

- Machine: JarvisLabs VM `425813`, H100 80GB x2, region `IN2`.
- Driver: `580.126.20`, CUDA runtime reported by `nvidia-smi`: `13.0`.
- Official Gemma revision: `d783c94c1446af43d5aa25a08b1b25984e387285`.
- Hackable Diffusion revision: `03ce88ed0acec3b17f4f284502a6053c5f2b3a15`.
- JAX package: `jax[cuda13]==0.10.1`.
- Recipe: official PubMedQA SFT geometry.
- Batch size: `2`.
- LoRA rank: `4`.
- Prompt length: `1024`.
- Canvases: `2`.
- Canvas size: `128`.
- Train loop: `hybrid`.
- Step synchronization: `losses`, which reads local addressable loss shards
  instead of forcing a full post-step state all-gather.

The runner follows the official DiffusionGemma runtime guidance used in the
Gemma repository for this backend:

```bash
XLA_FLAGS="--xla_disable_hlo_passes=constant_folding"
NCCL_ALGO=Ring
NCCL_PROTO=LL128
NCCL_NVLS_ENABLE=0
NCCL_CUMEM_ENABLE=0
```

It also initializes JAX and calls `jax.devices()` before importing TensorFlow or
Kauldron-heavy recipe modules. This avoids TensorFlow grabbing the CUDA runtime
first and causing JAX to fall back to CPU in this VM image.

Both runs completed one synchronized 26B PubMedQA LoRA train step and emitted
finite loss values. The two losses are not expected to be bit-identical because
these were independent stochastic runs, not a shared-seed deterministic parity
run. The important comparison here is same recipe, same checkpoint, same JAX
runtime, same official backend revisions, and successful completion through the
Tunix wrapper path.

## Verdict

The official DiffusionGemma backend is now verified on H100x2 in this
JarvisLabs VM when run with CUDA13 JAX, early JAX GPU initialization, official
NCCL/XLA settings, and local-shard loss synchronization.

The Tunix Hackable Diffusion wrapper is also verified under the same conditions.
This validates the wrapper path as a practical official-backend integration. It
does not claim that the native Tunix NNX/Qwix DiffusionGemma training graph has
matched the official 2-GPU memory profile yet.
